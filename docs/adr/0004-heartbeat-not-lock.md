# 4. Пульс вместо блокировки на время выполнения

Статус: принято

## Контекст

Чтобы задачу не забрали дважды, её надо как-то держать. Варианты: держать
блокировку базы всё время выполнения, либо отмечать владельца в строке и
периодически подтверждать, что он жив.

## Решение

Строка помечается владельцем, воркер обновляет `locked_at` раз в несколько
секунд. Сторож возвращает в очередь всё, у чего пульса не было дольше порога.

## Почему

Блокировка на двадцать минут - это открытая транзакция на двадцать минут. Она
мешает вакууму, блокирует выкатку схемы и рвётся при любом обрыве сети, причём
база узнаёт об этом не сразу.

Пульс даёт понятное поведение при падении: задача возвращается через известный
срок, и этот срок настраивается.

Побочный выигрыш: по ответу пульса обработчик узнаёт, что задачу у него отняли,
и может прекратить работу, не дожидаясь конца.

## Чем платим

Задача, чей воркер завис, но жив, будет висеть, пока не кончится порог. И есть
окно, в котором задачу уже вернули в очередь, а старый воркер ещё доделывает:
поэтому любая запись результата проверяет, что строка всё ещё наша.
