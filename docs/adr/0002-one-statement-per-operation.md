# 2. Каждая операция - одна SQL-команда, без транзакций

Статус: принято

## Контекст

Первая версия захвата была написана как транзакция: `BEGIN`, выбрать свободную
задачу, обновить, `COMMIT`. На обычном драйвере это работало. На HTTP-соединении
с базой, где каждый запрос идёт отдельно, транзакция разваливалась.

## Решение

Любая операция очереди - ровно одна команда. Захват сделан `UPDATE` с
подзапросом `FOR UPDATE SKIP LOCKED` внутри.

## Почему

Код переносится между драйверами без правок: обычное соединение, пул,
HTTP-доступ к базе.

Соединение не держится открытым дольше одного запроса. Это снимает целый класс
проблем: подвисшие транзакции, распухание таблицы, блокировки на выкатке.

Атомарность никуда не делась: одна команда в PostgreSQL атомарна сама по себе.

## Чем платим

Операции, которым нужны две таблицы в одной транзакции, так не выразить.
Пока таких нет: журнал шагов дописывается отдельно и его потеря не ломает
состояние задачи.

## Когда пересмотреть

Если появится операция, где рассогласование двух таблиц недопустимо.
